# JEAuditFlow 7.7 Native MySQL Database

This package contains repeatable schema files for `jeauditflow_770`, including the InnoDB JiraFlow snapshot table. It contains no existing user data or credentials and does not start Docker.

Use the matching 7.7 Deployment Support package and launcher to create the isolated native MySQL instance on `127.0.0.1:43324`. To copy existing 7.6 data, stop its application services and use the launcher's **Migrate 7.6 Data to 7.7** action before starting 7.7. That migration copies both database rows and version-specific files, verifies content hashes, and retains source backups.

To apply these SQL files to an already provisioned native instance, use the protected client configuration generated by the launcher:

```sh
export MYSQL_DEFAULTS_FILE="/absolute/project/local-deploy/runtime/native-mysql/7.7.0/app.cnf"
bash install-schema.sh --confirm "APPLY jeauditflow_770"
bash healthcheck.sh
```

`migrate.sh` applies the same idempotent schema to an existing 7.7 database. It does not copy 7.6 user data. Both write commands require the exact target-database confirmation. The client defaults file supplies credentials; the scripts fix the host to loopback and default to port `43324`. They never change the Docker Jira database.

Schema version 29 adds `jiraflow_state` to the previously accepted AuditFlow/FileAnalyst/shared-content tables. JiraFlow stores the current serialized application snapshot, revision, content checksum and counts together in one InnoDB transaction. The original `store.bin` remains as the preserved import source. InnoDB provides transactional commits, row locking and crash recovery; it is MySQL's storage engine rather than a separate database service.
